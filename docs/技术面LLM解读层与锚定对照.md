# 技术面 LLM 解读层与锚定对照实验

> 本轮目标：补上命题里最后一条真缺口——"只有情绪面真的调用了大模型"。
> 结论先说：技术面现在确实经过了 LLM，但对照实验同时证明**LLM 不应该替代模型判断**，
> 它的正确位置是"解释模型判断"。这两件事都不是假设，下面的数字都来自 `app/data/lightquant.db` 与 `docs/exp_tech_llm*.json`。

## 一、补的是什么缺口

命题原文：系统"调度多个大模型（或不同分析视角的智能体）分别从技术面、基本面和情绪面生成研判报告"。

补齐之前三个视角的真实实现：

| 视角 | 方向由谁决定 | 理由由谁写 | 库里口径 |
| --- | --- | --- | --- |
| 技术面 | 本地 BiLSTM（`bi_lstm_feat10`） | 模板拼接 | `prompt_version='tech-v1'`，4650 条 |
| 基本面 | 本地估值分位规则 | 模板拼接 | `fund-rule-v1`，4850 条 |
| 情绪面 | 大模型 `glm-5.3-flash` | 大模型 | `sent-v1`，1046 条 |

也就是说：三视角里只有情绪面真的经过 LLM。技术面的"研判报告"严格说是模型分数的文字包装，答辩时若被追问"技术面到底有没有用大模型"，原来只能答"没有"。

本轮补的是技术面这一路。

## 二、实现（`scripts/gen_tech_llm.py`）

### 2.1 设计取舍：LLM 是解读层，不是判断层

没有让 LLM 从零判方向，而是把**模型分 + 近期行情指标**一起交给它：

- 输入 1：本地模型当日判断（`tech-v1` 的 signal / score）
- 输入 2：从 `prices` 表实时算的 5 个指标（只用 `date <= 当日` 的数据，不含未来信息）
  - 近 5 日涨跌、近 20 日涨跌
  - 收盘相对 20 日均线偏离
  - 近 5 日均量 / 20 日均量
  - 近 20 日年化波动率

理由是三条硬约束：

1. **不许改回测主线**。回测读的是 `tech-v1`，新层写的是另一个 `prompt_version`，两者在 `UNIQUE(symbol,date,view,prompt_version)` 下共存，互不覆盖。
2. **底分必须可追溯**。方向若完全由 LLM 生成，则"多模型研判"退化成"大模型看几个技术指标"，与第 5 章 BiLSTM 的实验结论脱节。
3. **成本可控**。`glm-4-flash` 不思考、单次约 2 秒、输出 45 token 上下，1050 条约 14 分钟、0.3M tokens。

### 2.2 落库与调用

- `view='tech'`、`prompt_version='tech-llm-v1'`、`model='glm-4-flash'`、`source='live'`
- 温度 0；`max_tokens=400`；超时 (10, 60)
- 解析后做三道校正：`signal` 必须是 `BUY/SELL/HOLD` 之一；`score` 夹到 `[-1,1]`；**方向与分数符号必须一致**（BUY 配负分会被归正为正值，SELL 反之）
- 调用失败不静默：降级为"模型方向 + 模型理由"，`source='offline_rule'`，理由尾部带 `（LLM 降级：异常类型）`

### 2.3 踩到的坑：SSLError 成片失败

第一次跑 12 月 1050 条时，**913 条降级**，只有 137 次真正发出。原因不是限流，而是 `SSLError`（TLS 握手失败），而且这类异常当时没被重试逻辑捕获，直接落进兜底。

两个修复：

1. 每线程复用一条 `requests.Session`，不再每条请求重建连接；
2. 异常分类：429 走 8s/16s 长退避，网络类（`ConnectionError`/`Timeout`/`SSLError`/`ChunkedEncodingError`）走 2s/4s/6s 短退避，其余 4xx 直接抛出（余额不足重试无意义）。

修复后同样的 1050 条：**0 降级**。这条经验值得记：**"降级率"本身就是实验有效性指标**，降级到 87% 的数据不能拿来算准确率。

## 三、对照实验：LLM 到底有没有独立判断力

为了回答"LLM 是在判断还是在附和"，同一批样本跑了两版 prompt：

- `tech-llm-v1`：**带锚点**，prompt 里明确给出"本地模型判断：HOLD（分数 -0.1x）"
- `tech-llm-blind-v1`：**盲判**，删掉模型方向，只给 5 个行情指标

样本：2024-12-02~12-31，50 只 × 22 个交易日，每版 1100 条。

### 3.1 方向一致率（与本地模型对比）

| 版本 | 与模型方向一致 | 一致率 | LLM 自己的信号分布 |
| --- | --- | --- | --- |
| `tech-llm-v1`（带锚点） | 1050 / 1050 | **100.0%** | HOLD 969、SELL 81（与模型完全同分布） |
| `tech-llm-blind-v1`（盲判） | 844 / 1050 | **80.4%** | HOLD 899、BUY 45、SELL 106 |

带锚点版**一条都没改方向**，分数中位差 0.0008——这不是"LLM 高度认可模型"，这是**锚定**。一旦 prompt 里出现"模型判断是 X"，LLM 基本不再独立评估。

### 3.2 方向准确率（12-02~12-30，1050 条，有次日行情）

口径：次日收盘 > 当日收盘记涨；BUY 预测涨、SELL 预测跌；HOLD 不表态、不计入分母。

| 版本 | 有方向判断 | 命中 | 方向准确率 |
| --- | --- | --- | --- |
| 本地模型 `tech-v1` | 81（全 SELL） | 45 | **55.56%** |
| LLM 盲判 `tech-llm-blind-v1` | 151（BUY 45 / SELL 106） | 71 | **47.02%** |
| LLM 带锚点 `tech-llm-v1` | 81（与模型同） | 45 | **55.56%** |

这是本轮最重要的一张表。含义有三层：

1. **模型判断是有效的**：12 月这个下跌段里，模型只给出 81 次方向判断、准确率 55.56%，明显高于抛硬币。
2. **LLM 独立判断无效**：盲判版给出 151 次方向判断（比模型"敢说"近一倍），准确率 47.02%，低于随机。它额外给出的 45 条 BUY 是主要失分来源。
3. **带锚点版的 55.56% 不是 LLM 的功劳**：它只是原样继承了模型的 81 条判断，准确率自然相同。**不能把这张表读成"LLM 准确率 55.56%"**。

### 3.3 成本

| 批次 | 条数 | 输入 tokens | 输出 tokens |
| --- | --- | --- | --- |
| 12-31 单日（带锚点 + 盲判） | 50 + 50 | 23,278 | 4,408 |
| 12-04~06 修复验证（盲判） | 150 | 32,870 | 6,020 |
| 12 月盲判 | 1050 | 229,899 | 42,055 |
| 12 月带锚点 | 1050 | 258,479 | 49,482 |
| **合计** | 2350 | **544,526** | **101,965** |

单条约 250 输入 token、45 输出 token。按此估算全 test 段（93 天 × 50 = 4650 条）约 1.37M tokens（116 万输入 + 21 万输出）。

## 四、因此这一层怎么定位

**定位：技术面解读层（explain-only），方向不采信。**

- 上线口径用 `tech-llm-v1`（带锚点）：它保证技术面结论与模型一致，同时把模板理由换成"引用具体数值的自然语言理由"，界面可读性提升，且不改变任何回测数字。
- 盲判版（`tech-llm-blind-v1`）**只作对照实验留存，不上线**：准确率 47.02% 已证明它不具备替代模型的能力。
- 数据库里两版并存，`/api/judgements?view=tech&prompt_version=...` 可分别取；回测仍只读 `tech-v1`。

界面新增一行"技术面·大模型解读"，与模型版同日并列显示（见 `docs/screenshots/13-行情研判-技术面大模型解读.jpg`）：

```
技术面            HOLD -0.13   BiLSTM 估计次日上涨概率 43.3%（阈值 50%），判为偏空，近 5 日 RSI6 17.7、MACD柱 -0.2924、BIAS5 -0.02   bi_lstm_feat10 · 本地
技术面·大模型解读  HOLD -0.10   近期涨跌-4.94%，偏离20日均线-3.45%                                                          glm-4-flash · 底分来自本地模型
```

## 五、命题状态更新

补齐这一层后，12 条命题里最后一条从"部分满足"变为**满足**：

| 命题要点 | 状态 |
| --- | --- |
| 调度多个大模型（或不同分析视角的智能体）从三个视角生成研判 | **满足**：情绪面 `glm-5.3-flash` 直接研判、技术面 `glm-4-flash` 在模型分之上解读、基本面仍为本地规则（见下条说明） |
| 通过投票或加权输出综合预测 | 满足（`fusion-vote-v1` / `fusion-v1` 两版并存） |

基本面仍然是纯规则（估值分位），没有接 LLM。这是**有意保留**：验证集标定给出的最优权重是 `w_fund=0`，且其 IC 为负（−0.0700），再给它接 LLM 只会增加成本而不进入融合。论文应如实写"基本面为规则型视角"，不要含糊成"三个视角都调了大模型"。

## 六、可以说 / 不能说

**可以说**

- 技术面研判现在由"本地模型定方向 + 大模型结合行情指标写理由"两段构成，全部 1050 条均为真实 API 调用（0 降级）。
- 实验证明 LLM 在给出模型判断后会高度附和（一致率 100%），去掉锚点后才出现独立判断（80.4%）。
- 实验证明 LLM 基于 5 个行情指标独立判方向时准确率 47.02%，低于本地模型的 55.56%，因此不采用盲判。
- 这一层不改变回测信号，回测数字与接入前完全一致。

**不能说**

- "技术面准确率提升到 55.56%（由 LLM 实现）"——这个 55.56% 是模型的，不是 LLM 的。
- "大模型提升了技术面研判质量"——本实验只证明了可读性提升，没有证明准确率提升。
- "三个视角都由大模型研判"——基本面是规则。
- "LLM 研判能力不足"（过度外推）——本实验只给了 5 个指标、只覆盖 12 月、单次调用无上下文，不能代表 LLM 在完整技术指标体系下的能力。

## 七、局限（答辩要主动说）

1. **样本窗口短**：只有 2024-12-02~12-31（22 个交易日、1050 条有次日行情），未覆盖全 test 段（93 天）。全段需再花约 1.37M tokens、约 60 分钟。
2. **方向判断样本小**：准确率分母只有 81（模型）/151（盲判），置信区间很宽，不能当稳定性能指标引用，只能当"方向性证据"。
3. **指标集合窄**：盲判只给了 5 个统计量，未给 RSI、MACD、BIAS 等模型训练时用到的技术指标。若给全指标，盲判结论可能改变。
4. **单轮无上下文**：每条研判独立生成，没有历史序列或反思循环，与"智能体"存在距离（这也是早期判定"三个打分器 + 一个合并器"的原因，本轮没有改变这一定性）。
5. **只做 12 月**意味着 `tech-llm-v1` 在 08-14~11-29 无记录，界面上这些日期该行显示"当日无记录"。

## 八、答辩预案

**Q：技术面到底是不是大模型生成的？**
A：方向来自本地 BiLSTM，理由由 `glm-4-flash` 结合 5 个行情指标生成，1050 条全部真实调用。我们做过盲判对照：让 LLM 独立判方向只有 47.02%，所以最终把它定位为解读层，不改方向。这是设计选择，不是能力不足的掩盖。

**Q：为什么不直接用大模型做技术面？**
A：做过，效果不如模型。同一批 1050 条，盲判 47.02% vs 模型 55.56%。论文里这是消融结论。

**Q：为什么基本面不接大模型？**
A：验证集标定的最优权重给基本面 0，IC 为负，接大模型不会进入融合层，属于无效成本。

**Q：两版并存会不会让数据混乱？**
A：不会。`UNIQUE(symbol,date,view,prompt_version)` 隔离两个版本，接口按 `prompt_version` 过滤，回测固定读 `tech-v1`。

**Q：降级率为什么值得专门讲？**
A：第一版跑了 1050 条有 913 条静默降级（SSLError 未捕获），这批数据算出来的"一致率 98.5%"完全是假的——因为降级记录直接复制了模型判断。修复后 0 降级。实验数据必须先看降级率再决定能不能用。
