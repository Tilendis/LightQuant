# 认证与角色权限

本文说明四类角色（投资者 / 策略作者 / 风控员 / 运营）的身份是怎么验的、权限是怎么拦的，以及这套实现的边界在哪里。

## 为什么会有这份文档

早期版本的 `get_user` 直接读 `X-User-Id` 请求头：

```python
x_user_id: int = Header(default=None)
row = conn.execute("SELECT ... FROM users WHERE id = ?", (x_user_id,))
```

它拿客户端自报的数字去查角色。也就是说 **角色校验是真的，身份校验是假的**。实测：

```text
X-User-Id: 1  读 /api/risk/events  -> 403  角色 investor 无权
X-User-Id: 3  读 /api/risk/events  -> 200  直接拿到全部风控事件
```

把一个请求头数字从 1 改成 3，就获得了风控员权限。这不能算"四类角色权限隔离"，只能算"四类角色各自有菜单"。

## 两层分工

| 层 | 回答的问题 | 实现位置 | 失败返回 |
|---|---|---|---|
| 认证 Authentication | 你是谁 | `app/auth.py` + `get_user` | 401 |
| 授权 Authorization | 你能干什么 | `need(user, *roles)` | 403 |

两层是独立的两道门：认证先证明"你是 3 号"；授权再判断"3 号这个角色能不能看风控"。任一层不过都进不去。

## token 怎么签

不引 JWT 库——本项目的 token 只需要证明"这个 id 是服务端签发的"，HMAC 签名足够，且只有几十行，答辩能逐行讲。

```text
token = base64url(payload_json) + "." + base64url(HMAC-SHA256(secret, payload_json))
payload = {"uid": 3, "role": "risk", "exp": 1794571285}
```

签发：`POST /api/auth/login`，用户名 + 密码 → token。
校验：`get_user` 取 `Authorization: Bearer <token>`，重算签名比对，再查过期时间。

改动 payload 任何字段 → 签名对不上 → 401。改签名任何字符 → 401。攻击者没有 secret，伪造不出来。

## 密码怎么存

PBKDF2-HMAC-SHA256，10 万轮迭代 + 每用户随机盐，库里只存 `salt$derivation`，不存明文、不回传前端。

演示账号统一口令 `demo1234`，由 `POST /api/auth/demo-users` 幂等写入（该接口本身不需要认证，它是登录前的前置步骤）。

## 实测结果

| 场景 | 结果 |
|---|---|
| 风控员 token 读风控事件 | **200** |
| 投资者 token 读风控事件 | **403**（授权仍有效） |
| 完全不带 Authorization | **401** |
| 老的 `X-User-Id: 3` 冒充风控员 | **401**（老漏洞已封） |
| 把 payload 里 uid 改成 1，沿用原签名 | **401** |
| 签名改一个字符 | **401** |
| 错误密码 / 不存在的用户 | **401**，且两者返回同一句"用户名或密码错误"，不泄露账号是否存在 |
| 投资者 token 读策略列表、读自己账户 #5 | **200** |

31 个单元测试全部通过。

## 演示体验没有变差

前端没有加登录框。`init()` 会先调 `demo-users` 拿到演示账号和口令，再自动登录第一个账号；点角色按钮时调一次 `login` 换 token。所以答辩现场还是一键切四个角色，但底层走的是真签发、真验签。

状态栏会显示"风控员（id=3，已签发 token）"，可以直接指着它讲认证生效了。

## 这套实现的边界

写清楚，答辩被问到时不要硬撑：

1. **密钥存在本地文件** `app/data/.auth_secret`，与数据库同目录。本地演示够用，生产环境应放环境变量或密钥管理服务（代码里已支持 `LIGHTQUANT_SECRET` 环境变量优先）。
2. **token 无法主动吊销**。无状态签名的固有代价：签出去之后只能等它过期（当前 TTL 8 小时）。要做吊销得加服务端黑名单或会话表。
3. **没有 refresh token**。演示场景一次会话不超过 8 小时，不需要。
4. **没有密码强度校验、没有登录失败次数限制**。演示账号是预置的固定口令，不做这些；生产必须加。
5. **没有 HTTPS**。token 在明文 HTTP 上传输，本地 127.0.0.1 可接受，部署到公网必须上 TLS。

这些都写在代码注释和本文档里，属于"有意省略"而不是"没想到"。

## 复现方式

```powershell
# 1. 初始化演示账号（幂等）
Invoke-RestMethod -Method Post http://127.0.0.1:8014/api/auth/demo-users

# 2. 登录拿 token
$body = '{"username":"risk_demo","password":"demo1234"}'
$r = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8014/api/auth/login `
      -ContentType 'application/json' -Body $body
$r.token

# 3. 带 token 调接口
Invoke-RestMethod -Uri http://127.0.0.1:8014/api/risk/events `
  -Headers @{ Authorization = "Bearer $($r.token)" }
```
