# 复权口径与回测价格处理

> 结论先行：**当前数据集不提供复权因子**（150 个 CSV 的 `Adj Close` 与 `Close` 逐行相等）。
> 所以"回测用未复权价"是数据源限制，不是代码缺陷。但引擎已被改造成"有因子就正确用"，
> 且改动前后结果逐位一致——这一点由审计脚本、单测和等价性回测三方共同证明。

## 一、问题是什么

回测按日线 OHLC 撮合。如果价格序列没有做除权调整，除权日（送股、拆分、大比例分红）会出现
价格断崖：收益率被凭空放大或压缩，买卖价、止盈止损的触发价全部错位。这是量化回测里最常见的
一类静默错误——结果看起来正常，但口径已经错了。

## 二、先查数据，再动手

`scripts/audit_prices.py` 扫描 `dataset/CSMD50_feat/{train,val,test}/price/*.csv`：

| 检查项 | 结果 |
|---|---|
| 扫描文件数 | 150（train/val/test 各 50） |
| `Adj Close` 与 `Close` 完全相等 | 150 |
| `Adj Close` 有真实调整 | 0 |
| 疑似除权跳变（因子相邻变化 > 0.1%） | 0 |
| 结论 | `data_not_adjusted` |

审计结果落盘 `docs/price_audit.json`，含 150 条逐文件明细，可复现。

### 2.1 按段统计除权跳空（2026-11 补充）

上面的"疑似除权跳变 0"是**按因子相邻变化**判的（因子本身恒为 1，所以必然为 0）。
要判断"价格序列里到底有没有除权断崖"，得直接扫日收益率，且阈值必须**按股票代码分流**
（主板 10cm / 科创板 688 与创业板 300 为 20cm / 北交所 30cm）。按中文股票名判断板块会全部
落到 10cm，把 20cm 涨跌停误判成除权——这个坑踩过一次，结论不可信，已改为按 `stocks` 表的
`code` 分流重算：

| 段 | 文件 | 越阈值 | 其中疑似除权 | 疑似涨跌停 |
|---|---:|---:|---:|---:|
| train | 50 | 19 | **19** | 0 |
| val | 50 | 0 | **0** | 0 |
| test | 50 | 0 | **0** | 0 |

train 段 19 次全部为**负跳空**，且集中在 2021–2023 年 6–7 月除息季（中国神华 7 月、中远海控
6–7 月、山西汾酒 7 月、海天味业 5–6 月、国电南瑞 6 月、隆基绿能 6 月等），是真实的大额分红/
送转除权，不是数据错误。

**这条事实对结论很关键**：

- 回测窗口是 2024-03-15 ~ 2024-12-31（val + test 两段），这两段**除权跳空为 0**；
- 所以"用未复权价回测"在当前窗口里**实际没有引入除权误差**——不是"运气好"，是窗口恰好
  避开了 6–7 月除息季（val 段止于 08-07，test 段起于 08-08）；
- 但 train 段（2021–2023）有 19 次跳空，**若将来把回测扩到 train 段或跨年验证，未复权价会失真**，
  届时必须接入真实复权因子。

**这意味着**：CSMD 数据集的 `Adj Close` 列名义上是复权价，实际没有做除权调整。
单纯把 `df["Close"]` 换成 `df["Adj Close"]` 数值上不会有任何变化——那只是改了个名字，
不是修了工程问题。

## 三、代码怎么改

`backtest/engine_v2.py` 新增 `load_price_frame(path, look_back_window)`，把价格加载
从 `run_backtest` 的循环里抽成独立函数（可单测）：

1. 计算 `factor = Adj Close / Close`
2. 用 `factor` **同时缩放 `Close` / `High` / `Low`**
3. `Adj Close` 与 `Close` 全等时 `factor` 取 1——保证历史结果逐位可复现
4. 因子非正或非有限 → 直接抛 `ValueError`，不静默算出 inf
5. 数据有真实因子时，`Label` 按缩放后的价格序列重算（预生成的 Label 是按未复权 Close 算的，
   除权日的涨跌方向会失真）

**为什么必须一起缩放 High/Low**：止盈止损用 `High`/`Low` 判断触发。若只调整 `Close`，
除权日 `Low` 仍在除权前高位，止损会被永久误触发。这是"换列名"和"正确复权"的分界线。

**结果字段**（写入 `summary.json` 的 `portfolio`）：

| 字段 | 含义 |
|---|---|
| `price_basis` | `adj_close`（用了真实因子）/ `close_unadjusted`（因子为 1） |
| `price_adjusted` | 本轮是否有任何标的使用了非 1 因子 |
| `price_factor_jumps` | 累计检测到的因子跳变次数 |
| `files_with_factor` | 有真实因子的文件数 |

`checks` 新增 `price_basis_declared`，保证"这轮回测用的哪个价格口径"事后可追溯，
而不是只能靠回忆。

## 六、边界：没做什么

- `feature_engineering.py` / `utils/util.py` 仍用 `df["Close"]` 算特征与 label。因数据集两列相等，
  数值不受影响；**若更换数据源，这两处必须同步改**，否则特征与回测价格口径会分裂。
- `run_backtest_v2.py`（模型自身概率的链路）走同一个引擎，自动继承复权逻辑，未单独加参数。
- 数据源本身没有复权因子，无法凭空构造。系统只做到"有因子就正确使用"，不会伪造因子。
- **回测窗口外仍存在未处理除权**：train 段（2021–2023）有 19 次真实除权跳空，当前既没做因子、
  也没用这些日期跑回测，所以暂时不影响已产出的结论；一旦把回测扩到 train 段就必须先接因子。
- 只做了"按日收益率超板块阈值"这一种检测法。它能把除权挑出来，但也会漏掉跳空幅度小于
  10cm 的小额分红除息（每 10 股派几毛这类）。对已核出的 19 次大额除权是够的，对精细度更高的
  用途不够。

## 七、汇报口径：能说与不能说

**能说**

- 引擎按 `Adj Close/Close` 比值统一缩放 OHLC，数据带因子时自动生效
- 审计脚本可复现地证明了当前数据集未提供复权因子
- 改动前后 19 个指标逐位一致，有 24 个单测和一次全量回测对拍双重验证

**不能说**

- "系统已实现复权"——数据没有因子，实际仍按未复权价成交
- "回测结果已消除除权影响"——只能说"数据源未提供除权信息，引擎具备正确处理能力"
