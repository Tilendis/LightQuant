# 数据库表清单

> 由 `scripts/dump_schema.py` 从 `app/data/lightquant.db` 直接导出，不手抄——改表之后重跑一次即可，文档不会静默过期。
> 建表语句的唯一来源是 `app/schema.sql`；后加的列由 `app/db.py` 的 `_migrate()` 补齐。

共 **15** 张表。设计原则写在 `schema.sql` 开头：每张表都对应题目里一个可演示的业务动作，不留“以后可能用得上”的空表。

## 三条读表红线

1. **`valuations` 对齐到交易日必须 ffill，不得插值或回填。**否则 2024-09 的判断会用到 2024-10 之后才知道的估值，属于未来函数。
2. **`fundamentals` 用 `announce_date` 而不是 `period` 对齐。**2024Q3 的报告要到 10-31 才可见，用 period 对齐等于提前知道两个月。
3. **`judgements` 的 `source` 只有 live / cache / offline_rule 三种。**前端据此标「离线预计算」，不得把缓存结果说成实时调用。
