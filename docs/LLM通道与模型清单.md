# LLM 通道与模型清单

> 记录时间：2026-11-11。所有状态均为当日实测（`/compatible-mode/v1/chat/completions`，每个模型发一次 16–24 token 的探针请求）。
> 额度与到期日按百炼控制台显示，可能随账号变化，引用前请回控制台复核。

## 一、为什么要把"通道"和"模型"分开记

阿里百炼的一条 OpenAI 兼容通道上挂着**多家厂商的模型**：qwen（阿里）、deepseek（深度求索）、kimi（月之暗面）、glm（智谱）都在同一份免费额度列表里。

这意味着：

- `provider` 字段记的是**走哪条通道**（`dashscope`）
- `model` 字段记的是**调谁家的模型**（`deepseek-v4.1-flash`）

两者必须分开，否则会出现"provider 写 deepseek、实际走的是阿里通道"这种说不清的口径。`post_moderation.llm_verdict` 里同时记了两个字段，例如：

```
dashscope/deepseek-v4.1-flash: {"violation": true, "reason": "宣称策略保底年化三十个点并让用户跟着买，属于承诺收益。"}
```

同理，研判层的 `judgements.provider` / `judgements.model` 也是这个口径：情绪面记 `zhipu / glm-5.3-flash`，编排层记 `zhipu / glm-4-flash`。

## 三、审核层为什么选 deepseek-v4.1-flash

三条硬指标，都不是"口碑"：

| 维度 | deepseek-v4.1-flash | 其余候选 |
| --- | --- | --- |
| 延迟 | 1.8–2.3 s | 4.0–7.0 s |
| 输入 token | 117 | 145–169 |
| 额度剩余 | 67 天 | 6–20 天（kimi-k3.1-pro 除外，83 天） |

审核是**同步接口**（风控员点一下要出结果），延迟直接决定体验；而它每条只花 ~120 in / ~140 out，额度消耗极小。

厂商异质性方面：DeepSeek 与智谱 GLM 的底座、语料、对齐策略都不同，符合"错误来源独立"的前提。kimi 也可作为备选，额度更久但更慢。

## 四、什么不算"异质"

`glm-5.3` 在百炼里也能调，但它是**智谱自家模型**，和情绪面用的 `glm-5.3-flash` 同源。用它做"第二家"只换了通道、没换厂商，答辩经不起追问。同理，`qwen-flash` 与 `qwen3.8-flash` 是同一家。

## 五、怎么换模型（不用改代码）

`service_risk.py` 的 `_llm_settings()` 读两个环境变量，通道和模型分开配：

```powershell
# 通道（决定 base_url 与 key）
$env:MODERATOR_PROVIDER = 'dashscope'          # 阿里百炼
$env:DASHSCOPE_API_KEY  = '<key>'
# 模型（决定花哪份额度）
$env:MODERATOR_MODEL    = 'deepseek-v4.1-flash'
```

也可以写进 `%USERPROFILE%\.lightquant\secrets.env`（不在仓库里、不进 git），启动时由 `scripts/start_demo.ps1` 自动加载：

```
MODERATOR_PROVIDER=dashscope
MODERATOR_MODEL=deepseek-v4.1-flash
DASHSCOPE_API_KEY=<key>
```

改完重启服务生效。不配这两组变量时服务照常运行，审核退回规则层，接口 `detail` 会如实写"仅规则层（LLM 层未启用…）"，不会假装通过了模型。

## 六、额度够跑多少

按实测单条消耗算（不是按"一张大表格塞进 prompt"估算）：

| 场景 | 单条 token | 100 万额度可跑 |
| --- | --- | --- |
| 发帖审核（实测） | ~260 | 约 3800 条 |
| 编排层仲裁（`exp_orchestrator.json` 实测 354 in / 46 out） | ~400 | 约 2500 条 |
| 12 月全段研判对照（50 只 × 22 日 = 1100 条） | ~400 | 约 44 万 token，**在单模型额度内** |

结论：**免费额度足够跑完一个月量级的对照实验**，不需要先充值。但要注意额度是**按模型分别计的**，一条通道不等于一个池子——用完了某种模型就换另一种，不能"这个用完借那个的"。

## 七、三个已知的坑

1. **`max_tokens` 太小会让思考型模型输出空正文**。探针里 `kimi-k3` / `deepseek-v4.1-flash` 在 `max_tokens=16` 时 `content` 为空（`finish_reason=length`），给到 700 就正常返回。审核层已把 `max_tokens` 提到 400。
2. **RPM 限流会伪装成"模型不可用"**。`qwen-turbo` 一上来就 429。批量探测必须串行 + 间隔（本次用 1.2 s 间隔，12 个模型无一次 429）；批量研判要比对这个间隔再定并发数。
3. **到期日各不相同，且最长的和最快的不一定是同一个**。当前"最快"是 deepseek-v4.1-flash（67 天），"最久"是 kimi-k3.1-pro（83 天）。做长期实验前先看日期，别在快到期的那份额度上铺大工程。
