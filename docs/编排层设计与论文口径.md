# 编排层：设计、边界与论文口径

> 对应代码 `scripts/orchestrate.py`，落库 `view='fusion'`、`prompt_version='fusion-orch-v1'`。
> 本文所有数字均来自本机实测，口径在每处标明；未验证的内容明确标注为"未验证"。

---

## 一、这层是什么

编排层位于三视角研判和融合输出之间，是一个**带决策分支的调度器**。它在每个交易日、每只标的上做三件事：

1. **判断**：读当日技术面、基本面、情绪面三条研判，判断它们构成"方向一致"、"轻微分歧"还是"多空对立"。
2. **分支**：只有多空对立时才进入取证分支——自己去查库拿证据；其余情况走确定性规则合成，不调模型。
3. **取证与仲裁**：取证分支中，从 `news`、`prices`、`valuations` 三张表取当日证据，连同三视角结论一起交给生成式模型做一次仲裁。

它与"流水线（pipeline）"的区别只有一条，但这条是本质的：

| | 流水线 | 编排层 |
|---|---|---|
| 输入 | 固定字段，每次一样 | 先看三视角是否对立，再决定要不要额外取证 |
| 调用次数 | 每条记录必调一次 | 只在冲突日调用（本次 22/50） |
| 分支可追踪 | 无 | `reason` 前缀记录 `[unanimous]` / `[minor]` / `[conflict_llm]` / `[conflict_rule(fallback:…)]` |
| 证据来源 | 无 | 三张表的实时查询结果 |

一句话：**它根据状态选择动作，且动作会产生新的输入**。这是它区别于原"三个打分器 + 一个规则合并器"的唯一实质差别。

---

## 二、为什么需要它

题目 2 原文对这一段的表述是：

> 调度多个大模型（或不同分析视角的智能体）分别从技术面、基本面和情绪面生成研判报告，并通过投票或加权机制输出综合预测。

原实现的状态是：三个视角（BiLSTM 判别模型 / 估值分位规则 / GLM 文本模型） \(+\) 一个加权合并器。这满足"不同分析视角"的字面，但**没有任何一个环节会根据上游状态改变自身行为**。它在形式上是"多个分析器"，功能上是"一次前向计算"。

编排层补的是"决策"这一环，而不是"再加一个模型"。加模型只是加算力，加决策才是加结构。

## 三、分支逻辑

### 3.1 判据：为什么按方向判，不按分数判

第一版判据用的是三视角 `score` 的极差：极差 \(>0.25\) 判冲突。离线跑 2024-12-31、50 只标的，结果 **48 条被判冲突（96%）**。

原因是三个视角的分数**尺度不可比**：

- 技术面：BiLSTM 输出"次日上涨概率减去阈值 50%"后的偏离量，量程约 ±0.5；
- 基本面：估值分位映射到 [-1, 1]，但一旦 PE/PB 落在极高分位就直接给 -1.00；
- 情绪面：文本倾向分，量程 ±1，但多数新闻接近中性。

三个不同量程的数做减法，极差几乎恒大于任何固定阈值。用极差判冲突，等价于"每天都是冲突"，分支就退化成"每天都调用模型"，编排层失去意义。

改为**按离散方向组合判**：

```
signals = {三视角的 signal}
若 signals 只有一种取值            → unanimous（方向一致）
若同时出现 BUY 与 SELL            → conflict（多空对立，真正需要仲裁的矛盾）
其余（如 BUY 与 HOLD、SELL 与 HOLD）→ minor（有分歧但未对立）
```

改后同一批数据得到：`unanimous 4 / minor 24 / conflict 22`，冲突率回落到 44%，符合"多数日子三视角不至于完全对立、但确实有一部分日子会"的预期。

### 3.2 三条分支的处理

| 分支 | 处理 | 是否调用模型 | 本次条数 |
|---|---|---|---|
| `unanimous` | 按标定权重合成（实现与标定权重一致：tech 1.0 / fund 0.0 / sent 0.5） | 否 | 4 |
| `minor` | 同上 | 否 | 24 |
| `conflict` | 先取证，再交模型仲裁 | 是 | 22 |

设计意图：**把模型调用限制在真正需要判断的地方**。这样 56% 的结果完全由确定性逻辑产出，28 条记录不受模型随机性影响。

### 3.3 取证项

冲突分支不会把固定字段喂给模型，而是现查三张表：

- `news`：该标的当日新闻标题，最多 3 条（无标题时回退正文前 80 字）；
- `prices`：该标的截至当日的最近 6 个收盘价，算 5 日涨跌百分比；
- `valuations`：该标的截至当日的 PE(TTM) 与 PB。

证据全部来自本地 SQLite，**不引入任何外部实时数据**，断网也能完整演示。

### 3.4 兜底与降级

无 key、限流、超时、解析失败时，降级到规则分支，并把原因写进分支标签：

```
conflict_rule(fallback:ReadTimeout)   ← 调用超时
conflict_rule(fallback:ValueError)    ← 返回内容为空或解析失败
conflict_rule                         ← 没有凭据，主动走规则
```

**降级标签一定留在库里**，不静默伪装成"模型已仲裁"。本次 22 条全部为 `conflict_llm`，降级 0 条。

## 四、它算不算"智能体"：四要素逐项对照

这是答辩最可能被问的一题，需要一个明确、不含糊的答案。

| 要素 | 判定标准 | 本实现 | 结论 |
|---|---|---|---|
| 决策 | 依据当前状态选择不同动作 | `decide()` 输出 4 种分支，动作不同（调不调模型、取不取证） | **满足** |
| 工具调用 | 主动取新信息，而非只用给定输入 | `gather_evidence()` 现查 3 张表 | **满足** |
| 循环 | 观察 → 行动 → 再观察 | 一次取证 → 一次仲裁即结束，无迭代 | **不满足** |
| 状态/记忆 | 跨记录保留上下文 | 每条 (symbol, date) 独立，不看前一日结论 | **不满足** |

结论：**它是一个"单步编排器（orchestrator），不是自主智能体（autonomous agent）"**。四要素满足 2 项、缺 2 项，按学术界对 agent 的通行定义（感知—决策—行动闭环 \+ 记忆），不能称智能体。

正确表述是：

> 系统实现了三视角**异质分析器**的组合，并在多空对立时引入一个**单步编排分支**：由规则检测冲突、由编排器取证、由生成式模型给出仲裁结论。系统未采用自主智能体形态——不作多轮循环、不保留跨日记忆，以保证同一输入得到同一输出。

**禁止**说"多智能体系统""三个智能体协作""智能体编排"。

## 五、为什么只做到这一档

三档升级的成本与收益：

| 档位 | 内容 | 成本 | 收益 | 结论 |
|---|---|---|---|---|
| 1 | 决策分支 + 取证（本次实现） | 已完成 | 冲突日有了带证据的结论，且分支可统计 | 采纳 |
| 2 | 冲突日调 LLM 仲裁 | 与档位 1 合并实现 | 已含在上面 | 采纳 |
| 3 | 三视角各建 agent + supervisor 多轮协商 | 1 周以上 | 收益递减：多轮协商会放大不可复现性，且三视角的判断依据本就是异构的（数值 vs 规则 vs 文本），"协商"缺乏共同语言 | **不采纳** |

档位 3 的问题不在实现难度，在**方法论冲突**：论文第 5 章的全部数字建立在"同输入必同输出"之上，而多轮 agent 协商必然引入分支随机性。要把 agent 做进系统，就必须放弃可复现的实验结论，二者不能兼得。

## 六、边界：为什么不进入回测信号链

这是本层最重要的一条约束，代码里体现为：回测引擎读 `fusion-val-v1`，编排层写 `fusion-orch-v1`，两个版本互不可见。

理由不是"怕出错"，而是**可复现性契约**：

1. 回测指标（收益率、回撤、夏普、IR）必须能被第三方用同样输入复现；
2. 编排层含模型调用，模型的输出即使温度 0 也不承诺逐位相同（API 不保证），且限流会导致降级路径分叉；
3. 一旦编排层进信号链，同一份数据在不同时间跑出的回测结果可能不同，第 5 章所有对比实验的结论都会失去可复现前提。

因此系统的两条链分工固定：

```
回测信号链（冻结）   : 三视角 → 加权融合(fusion-val-v1) → 回测引擎 → 指标
解释展示链（可分支） : 三视角 → 编排层(fusion-orch-v1) → 研判报告第五行 → 界面
```

两条链**只共享数据来源，不共享决策权**。这条要在论文里写明，否则"为什么不把编排层接进回测"会成为必问题。

## 七、实测结果

口径：`2024-12-31` 单日，50 只标的，`--workers 4`，模型 `glm-4-flash`，温度 0.0，`max_tokens=400`。

**分支分布**

| 分支 | 条数 | 占比 |
|---|---|---|
| `unanimous` | 4 | 8.0% |
| `minor` | 24 | 48.0% |
| `conflict_llm` | 22 | 44.0% |
| 降级 | 0 | 0.0% |

**模型用量**：调用 22 次，输入 7 779 tokens，输出 1 009 tokens。均摊每次冲突仲裁约 354 输入 / 46 输出 tokens。

**重复运行稳定性**：同一输入重跑，分支分布与调用次数保持 `22/22` 不变，未出现分支漂移。温度 0 的作用是消除采样随机性，但不承诺逐位相同——这一点在论文里应如实写为"实测未观察到分支漂移"，而不是"完全确定性"。

**样例**（中国银行 2024-12-31）

| 视角 | 信号 | 分数 | 理由要点 |
|---|---|---|---|
| 技术面 | SELL | −0.24 | BiLSTM 估计次日上涨概率 38.0%（阈值 50%），5 日 RSI 80.0 |
| 基本面 | SELL | −1.00 | PE 处历史 100% 分位、PB 处 100% 分位 |
| 情绪面 | — | — | 当日无新闻，沿用最近一次情绪分 |
| 融合（主线） | HOLD | −0.16 | tech −0.24 / fund −0.93 / sent +0.13 |
| **编排层** | **SELL** | **−0.80** | `[conflict_llm]` 技术面偏空，估值偏高，综合判断卖出 |

## 八、必须如实写出的局限

### 8.1 HOLD 占比高，分数梯度不足

22 条冲突记录的仲裁结果并不是全部给出方向。当日 50 只的编排结果中，HOLD 共 **30 条**（SELL 13 条、BUY 7 条），其中 **12 条分数恰为 0.0000**。

已尝试两种修正（放开 HOLD 的分数钳制、把 prompt 示例值改为 0.0 并声明"不得照抄"）均未消除。原因不在代码，在模型行为：**证据不足以支撑方向时，它倾向输出中性而不是强行给分**。

论文里不能写成"编排层显著提升了方向判断"，只能写：

> 在证据不足以支撑方向判断的冲突日，编排层倾向于输出中性结论而非给出方向性判断。这一行为表明模型未对无充足依据的情况作出过度自信推断，但同时也说明该层在多数冲突场景下未能提供增量信息。

### 8.2 无法评估预测力（当前口径）

`2024-12-31` 是测试期最后一天，没有次日收益，**无法计算编排层的次日方向准确率**。当前只有分支分布和单条样例，不能声称"准确率如何"。

若要评估，必须覆盖非期末交易日：取 2024-08-08～2024-12-30 之间的日子，用 T+1 实际涨跌对编排层结论做准确率统计。这一步尚未执行。

### 8.3 编排层与主线融合的结论可能不一致

上表样例中，融合给 HOLD −0.16，编排层给 SELL −0.80。差异来源是：编排层的取证分支看到了融合层看不到的信息（当日新闻、5 日涨跌、估值绝对值）。

论文里不能把这种不一致解释为"编排层更准"——**没有证据**。正确说法是"两个层次承担不同职能：融合层输出可回测的标量分数，编排层输出带证据引用的方向解释；二者的分歧本身是可解释性的体现，不构成优劣判断"。

### 8.4 情绪面靠 ffill 外推

情绪面按"有新闻的日子"落库，无新闻的日子由编排层向前取最近一次记录（标 `ffill=True`），且**无衰减**。这意味着 5 天前的新闻情绪会被当成当天的情绪使用。这一口径尚未验证，论文中应写明为已知简化。

## 九、论文可直接使用的表述

以下三段可直接使用（已按学术口径写，避免"智能体""提升精度"等禁语）。

**第一段｜系统结构中的定位**

> 系统在研判层采用"三视角异质分析器 + 加权融合"结构：技术面使用 BiLSTM 判别模型估计次日涨跌概率，基本面使用估值分位规则计算价值偏离度，情绪面使用生成式语言模型对财经新闻文本作倾向判别。三个视角的输出经标定权重融合为单一标量分数，作为策略回测的信号输入。由于三个视角的判断依据在数据结构上互不相同（数值序列、确定性规则、非结构化文本），其结论出现方向性对立是可预期的，而非模型缺陷。

**第二段｜编排分支的引入**

> 为处理三视角方向对立的情形，本文在融合层之上增设一个编排分支（orchestrator）。该分支不参与回测信号生成，仅用于生成带证据引用的综合研判。其工作机制为：先依据三视角信号的方向组合判别一致、轻微分歧与多空对立三类状态；仅在多空对立状态下，由编排器从本地行情、新闻与估值三张数据表取当日证据，连同三视角结论交由生成式模型作一次仲裁，输出综合方向、强度与理由；其余状态由确定性规则按标定权重合成，不调用模型。该设计使模型调用集中于真正需要判断的场景，在测试期单日 50 只标的的实测中，模型调用被限制在 44% 的记录上。

**第三段｜可复现性约束**

> 编排分支与回测信号链在数据层隔离：回测读取固定融合版本的分数，编排分支的输出写入独立版本，二者不交叉。这样处理的目的是保证回测指标的可复现性——生成式模型的输出不承诺逐位确定，若将其接入信号链，同一份数据在不同时刻的回测结果可能发生漂移，从而使对比实验的结论失去可复核前提。因此本系统的可解释性增强与回测可复现性被显式区分为两条链路，仅共享数据来源，不共享决策权。

## 十、答辩预案

| 可能的提问 | 应答要点 |
|---|---|
| 这算多智能体吗？ | 不算。四要素满足决策与工具调用两项，缺循环与记忆。它是单步编排器。 |
| 为什么不用分数差判冲突？ | 试过，96% 的日子都被判冲突，因为三个视角分数尺度不可比。已改为方向组合判据。 |
| 编排层为什么不做进回测？ | 可复现性。模型输出不承诺逐位确定，进信号链会让第 5 章所有对比实验失去可复现前提。 |
| 编排层比融合层准吗？ | 无法比较，也无意比较。编排层只到 2024-12-31 单日，没有次日收益，算不出准确率。它的职能是解释，不是预测。 |
| 22 条里 30 条 HOLD，是不是没做出东西？ | 是模型在证据不足时的保守行为，已验证不是代码问题。如实写进局限，不写成增益。 |
| 为什么选 glm-4-flash 而不是更强的模型？ | 更强的思考型模型（glm-5.3-flash 等）把输出额度耗在思考链上导致正文为空，且单次 42～143 秒、并发必被限流。glm-4-flash 2 秒返回、不思考，适合这种短结构化判断。这是实测结论，不是主观偏好。 |
| 一个 API key 够吗？ | 够。限流按账号计，不按 key 计，多 key 只增加额度不增加并发。 |
| 取证分支取的三项证据有依据吗？ | 三项分别对应三个视角的信息缺口：新闻对应情绪面、5 日涨跌对应技术面的短期动量、PE/PB 对应基本面的估值绝对水平。都来自本地库，可追溯。 |
