# 截面选股策略与可执行口径

本文件记录第二类策略（截面选股）为什么做、怎么验证、结果能讲到什么程度。
与 `融合主口径与情绪面覆盖口径.md`、`基本面口径与财报事件验证.md` 是同一套数据的不同切面。

---

## 一、为什么要加这条策略

主口径是**单标的择时**：整仓跟随一只股票的融合信号。课题要求"策略作者配置回测并发布"，
只有一种策略类型时，这个界面上的"配置"实际只剩止盈、止损两个数，谈不上策略多样性。

技术面分数在**截面**上有排序能力（val 段 top10 与 bottom10 的多空差 +0.660%，t=4.99）。
把它从"单标的择时"改成"50 只池内排序、取 top N 等权持有"，就得到第二种策略类型。
这是纯回测侧的改动，**不碰跟单链路**——范围内明确限定过。

---

## 二、可执行口径检验（这一节是全篇的立足点）

之前的 +0.660% 用的是 `adj_close(T+1)/adj_close(T)`，相当于 **T 日收盘就成交**。
但 tech score 要用 T 日收盘数据才能算出来，最早只能 **T+1 开盘下单**——隔夜跳空拿不到。

三种口径重算（`adj_open = open × adj_close/close`，避开除权跳空）：

| 口径 | val（89 天） | test（92 / 91 天） |
|---|---|---|
| ① 收盘 → 次日收盘 | top10 +0.308% / bottom10 −0.352% / 差 **+0.660%**（t=4.99） | +0.566% / +0.011% / 差 **+0.554%**（t=2.85） |
| ② 次日开盘 → 次日收盘 | +0.372% / −0.174% / 差 **+0.546%**（t=4.47） | +0.404% / −0.032% / 差 **+0.436%**（t=2.98） |
| ③ 次日开盘 → 再日开盘 | +0.309% / −0.329% / 差 +0.638%（t=4.71） | +0.567% / +0.098% / 差 +0.468%（t=2.70） |
| 隔夜跳空贡献 | +0.114%（t=2.69） | +0.118%（t=1.33） |

**结论**：去掉隔夜跳空后，两段独立窗口方向一致、仍然显著。这不是靠跳空撑起来的。
这是整个项目里**唯一一个两段都验证过、且可执行**的信号。

## 三、成本敏感性（K=1，每天全换）

| 滑点 | val | test |
|---|---|---|
| 0.05% | +8.75% | +32.78% |
| 0.10% | +2.44% | +24.12% |
| 0.20% | **−9.12%** | +8.43% |
| 0.30% | −19.38% | −5.29% |

A 股日频全换仓的现实滑点是 0.2% 上下，**在这个值上 val 段已经转负**。
这条表本身就是工程内容：参数能把策略从赚变成亏。

## 四、降低调仓频率反而更好（滑点 0.20%）

| 持仓 K（交易日） | val | test | val MDD | test MDD |
|---|---|---|---|---|
| 1 | −9.12% | +8.43% | 14.10% | 23.51% |
| 3 | +11.66% | +34.87% | 5.13% | 8.75% |
| **5** | **+14.91%** | **+57.77%** | 5.72% | **3.47%** |
| **10** | **+15.43%** | +46.78% | **2.01%** | **1.45%** |

K=5 是收益与成本的平衡点，也是系统默认值。K=10 回撤更小但 test 收益掉下来。

> 收益恒为 0、只扣成本，全部为负。改成 `open_after[hold+1]` 才对。

## 五、集中度审计（把 57.77% 打回原形）

| 段 | 全部 | 去掉最好 1 次 | 去掉最好 2 次 | 去掉最好 3 次 | 该段基准 |
|---|---|---|---|---|---|
| val | +14.91% | +8.66% | +4.40% | **+0.84%** | −1.89% |
| test | +57.77% | +27.13% | **+15.40%** | +8.09% | **+19.04%** |

- test 段 **2024-09-20 那一次调仓的篮子毛收益 +24.54%**，正好压中 9/24 政策行情。
- val 段 18 次调仓 13 正 5 负，最大单次 +5.76%，**没有极端值**——val 是稳定小胜。

**判断**：val 段有稳定正 alpha；test 段靠一次行情放大。
把 test 的 57.77% 当卖点讲，被问一句"9 月底贡献了多少"就答不上来。

## 六、引擎实跑结果（`backtest/engine_cross_section.py`）

| 段 | 调仓次数 | CumRet | ARR | SR | MDD | 成交笔数 | 手续费 | 基准 CumRet | 基准 MDD | IR |
|---|---|---|---|---|---|---|---|---|---|---|
| val | 18 | **12.13%** | 34.64% | 1.740 | 6.76% | 350 | 3630 | **−13.65%** | 16.70% | 4.661 |
| test | 20 | **28.99%** | 95.09% | 1.836 | 14.00% | 370 | 4075 | **+14.63%** | 13.30% | 1.737 |

> 口径更新（2026-11-19）：本表 test 行已按当前 `tech-v1` 分数重跑（产物 `api_cs_new`）。旧口径的 53.80% / SR 3.676 / MDD 5.29% 是技术面前视泄漏修复前的数字，已作废，不再引用。稳健性检验同步重算：剔除最好 1/2/3 个调仓段后策略降至 −6.09% / −13.33% / −17.55%，同期基准 −13.87% / −14.52% / −19.58%，最好单段贡献 37.36%。

自检 8 项全部通过（`nav_len_matches_dates` / `no_nan_in_nav` / `no_negative_equity` /
`mdd_span_covers_trough` / `mdd_equals_recomputed` / `metrics_finite` /
`rebalance_executed` / `price_basis_declared`）。

与粗算（val +14.91%）差 2.78pp，原因是最低佣金 5 元与调仓日定义差异。

**为什么不复用 `engine_v2.run_backtest`**：那套是"每只股票各开一个 10 万账户、
最后 `navs.mean(axis=0)` 等权平均"。截面策略每天只持有 top N、其余空仓，
套进去 40 只空账户净值恒为 1，会把组合收益稀释成 1/N。所以新建了共享资金池的实现，
但指标、自检、输出格式与 `engine_v2` 完全同口径。

### 稳健性（引擎内计算，直接进回测报告）

按调仓周期切段、去掉收益最好的 1/2/3 段后重算累计：

| 段 | 全部 | 去最好 1 段 | 去最好 2 段 | 去最好 3 段 | 最好单段 |
|---|---|---|---|---|---|
| val | 11.86% | 6.27% | 1.11% | **−2.01%** | 5.26% |
| test | 28.99% | **−6.09%** | −13.33% | −17.55% | 37.36% |

**test 去掉最好一次调仓就变成 −6.09%；同期基准同段剔除后是 −13.87%，策略少亏 7.78pp，但正收益本身完全依赖 9 月底那一段。**
这个指标做成了报告里的固定字段（`portfolio.robustness`），不是事后手算。val 行尚未重跑，等 val 段重跑后同步。

## 七、口径差异（放进同一张表前必须处理）

| 项 | 截面引擎 | 主口径（`test_fusion_3view`） | 原因 |
|---|---|---|---|
| test 起点 | 2024-08-08 | 2024-08-14 | 主口径要 `look_back_window=5` 跳过前 4 行；截面直接从有分数的第一天开始 |
| test 基准 | 14.63% | 19.04% | 08-08~08-13 那几天正逢反弹，多算进来基准更高 |

**跨策略对比必须先统一起点，或在表里注明起点不同。** 直接横比是不成立的。

另外 ACC 也有两个含义：
- 主口径 ACC = 次日方向准确率
- 截面 `per_stock_mean.acc` = **被选中后持有期内上涨的占比**（val 0.6230 / test 0.6270）

这两个数不能放在一起比大小。

## 八、能讲什么 / 不能讲什么

**能讲**
- 策略类型多样性：课题要求"策略作者配置回测"，现在真的有两条路径可选、可在界面配置。
- 参数敏感性本身就是工程内容：滑点 0.05% → 0.30% 能把同一条策略从 +32.78% 打到 −5.29%。
- 稳健性检验做成了回测报告的固定指标（去掉最好 N 次调仓），不是事后挑数。

**不能讲**
- 不能说"截面选股是新技术突破"——它与主口径同源，是同一个 `tech-v1` 模型换了一种用法。
- 不能把 +0.660% 当策略收益——那是多空差，A 股不能做空。
- 不能说 test 段 28.99% 是选股能力——去掉最好一段调仓就变成 −6.09%，最好单段贡献 37.36%。
- 不能把这里的 ACC 0.6230 与主口径的次日方向准确率混为一谈。

## 九、同源问题（答辩必被问）

问题：这不就是把同一个模型换个用法？

回答：**是的。** 融合主口径里的技术面和这里用的 `tech-v1` 是同一个 BiLSTM 模型，
只是从"单标的择时"换成"50 只截面排序"。这条实验证明的是**该模型的信息含量不只一种用法**，
不是发现了新模型。如实讲这一点，比包装成"多策略体系"更站得住。

## 十、复现方式

```powershell
# 界面：策略作者 → 策略回测 → 策略类型选"截面选股" → 提交
# 接口：
POST /api/backtest/tasks
{
  "strategy_type": "cross_section",
  "start": "2024-08-08", "end": "2024-12-31",
  "top_n": 10, "hold_days": 5, "slippage_rate": 0.0020,
  "initial_cash": 100000.0
}
```

区间约束：截面策略**不支持跨 val/test 两段**（两个价格目录日期不连续），
跨段会直接报错而不是静默只用其中一段。

产物：`backtest/result_v2/<tag>/` 下 `nav.csv` / `trades.csv` / `per_stock.csv` / `summary.json`，
格式与 `test_fusion_3view` 对齐。

界面证据：`docs/screenshots/17-策略回测-截面选股策略.png`。

## 十一、测试覆盖与一个实测出来的缺陷

`backtest/engine_cross_section.py` 是这条策略唯一的执行路径，此前**零测试**。
它同时是答辩亮点（test 28.99% / SR 1.836），一旦现场跑出错就是当场翻车，所以补齐。

`tests/test_engine_cross_section.py`，12 个用例，2026-11-14 加入：

| 测什么 | 为什么必须测 |
|---|---|
| 分数取自 `dates[i-1]` | 取当日就是未来函数。用例只在调仓前一日给分，断言首个 BUY 落在 `i` 日 |
| 调仓清空旧仓 | 不清空则持仓滚雪球，仓位超 100%，净值曲线好看但不可实现 |
| `_load_panel` 的 `Open` 也跟复权 | 只调 `Close` 会让"开盘价 × 股数"的成交金额与净值脱节，手续费也算错 |
| 日期不对齐抛 `RuntimeError` | 静默对齐会让某天缺价的股票在组合里"消失" |
| 复权因子为负/非有限抛错 | 否则会算出负的成交金额 |
| `top_n` 上限 | 防止越买越多 |
| `nav` 长度 == 日期长度、现金非负 | 组合口径的基本正确性 |
| `stop_loss_exits` / `take_profit_exits` 恒为 0 | 截面策略不做止盈止损，字段必须是真值不是残留 |
| `summary.json` 无 `NaN` | 前端 `JSON.parse` 遇到 `NaN` 整页挂掉 |
| 稳健性剔段后收益 <= 全段 | 反了就是剔段算法写错 |

### 跑测试时抓到的真缺陷

`robustness.cum_drop_best_1/2/3` 在**调仓周期数不足 k** 时会写成 `float("nan")`，
`json.dump` 默认把 `NaN` 原样输出成 `NaN`——这不是合法 JSON，前端 `JSON.parse` 直接抛异常，整页白屏。

同一类坑此前已在 `per_stock_mean` 避开（那里只留四个字段并注释了原因），`robustness` 漏了。

修法：新增 `_jsonable()` 递归把 `NaN/Inf` 与 numpy 标量转成 JSON 合法值，`NaN` 一律写 `null`；
`json.dump(_jsonable(summary), ...)`。前端 `pct(null)` 本来就渲染成「—」，语义上也正好是"算不出来"。

触发条件不止测试环境：`hold_days` 设得大、或区间只够一两次调仓时，真实回测就会命中。
