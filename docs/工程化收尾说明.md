## 一、`scripts/selftest.py`：一条命令验证整套接口

**为什么需要**：答辩机器不一定装了 pytest，也不一定连得上外网。这份自检只用标准库 `urllib`，不依赖 requests / httpx / pytest。

**设计取舍（写在文件头注释里）**：

- **默认只读**。GET 接口全打一遍；写接口只做「预期被拒」的负测试（401 / 403 / 400）。这些请求在写库之前就被拦下——认证在 `get_user()`、授权在 `need()`、参数校验在 `normalize_params()`，所以可以反复跑不产生脏数据。
- 唯一写库的是 `--seed`（调 `POST /api/auth/demo-users` 建四角色），默认关闭。
- 退出码 0 / 1，可直接接 CI。

**当前覆盖 79 项**，分组：

| 组 | 项数 | 内容 |
|---|---|---|
| 健康与行情 | 5 | 12 表计数、行情区间、引擎预热、50 只标的、195 根 K 线 |
| 认证 | 6 | 无 token → 401、伪造 token → 401、四角色登录角色正确、错密码 → 401 |
| 研判与数据 | 8 | 四视角信号位、研判列表、财务 4 期、不存在标的 200 空数组、准确率 4 视角 + 统计窗口 |
| 回测 | 6 | 60 个结果目录、主口径在列、指标 / 净值 / 交易 / 回撤区间 |
| 订阅与跟单 | 9 | 订阅列表、净值曲线、持仓可复算、作者读他人账户 403、不存在账户 404 |
| 风控与审核 | 8 | 事件 6 条、5 个账户带强平字段、水位字段够算页面汇总（`liquidate_nav`/`max_dd_pct`/`event`/`as_of`）、投资者扫描 403 |
| 越权矩阵 | 8 | 投资者提交回测 403、看运营看板 403；作者读风控事件 403 |
| 参数校验 | 5 | 止损传 8 → 400、fusion 混用 → 400、未知融合版本 → 400、投票配加权表 → 400 |
| 研判调度 | 5 | 三视角 `write=false` 调度 200、返回 views+fusion、`written` 为空、投资者 403、删主口径版本 400 |
| 跟单推进 | 5 | 交易日历 200 且覆盖 2024-03-15~12-31、批量推进 200、返回 `mode/moved/skipped`、推进到非交易日 → 400 |

**幂等验证**：连续跑两遍都是 79/79 过，`/api/health` 的 12 个 counts 逐项不变，`judgements` 总行数不变（研判调度那一组走 `write=false`，不落库；跟单推进那一组在库内账户都已到期末时只返回 skipped，不改任何净值）。

> 上表各组数字是该组的检查条目数，个别检查共用同一次请求（同一份响应里断言多条），所以逐组加总不等于 79；以脚本末尾打印的「合计 N 项」为准。

```powershell
.\.venv\Scripts\python.exe scripts\selftest.py
```

## 三、补三个接口

| 接口 | 角色 | 说明 |
|---|---|---|
| `GET /api/follow-accounts/{aid}/positions` | investor / risk | 持仓明细，从策略 `trades.csv` 现算，移动加权平均成本 |
| `POST /api/follow-accounts/{aid}/liquidate` | risk | 手工强平，必须写一条带 `handled_by` 的事件 |
| `POST /api/subscriptions/{sid}/cancel` | investor | 取消订阅，只能取消自己的 |

**为什么持仓要现算而不存表**：模拟跟单是「用策略净值曲线等比缩放」，持有什么由策略决定。存一份会和 `trades.csv` 形成两个真相来源，改一次回测就两边对不上。

**口径要说清的边界**：`engine_v2` 是「每只股票独立 10 万账户再等权平均」，所以 `trades.csv` 里的股数 / 市值是策略内**单票口径**。乘账户净值会得到荒唐的数（2066 股 × 10 万），所以接口不提供「换算系数」，只返回 `account_current_nav` 与 `strategy_portfolio_nav` 两个参照值，并在 `note` 里写明这不是账户真实持仓。

**手工强平与取消订阅的语义区分**：两者都让账户停止推演，账户统一置 `LIQUIDATED`（表里只有 ACTIVE / LIQUIDATED 两个状态），但 `risk_events.detail` 必须写清是哪一种——否则风控面板上分不清「被强平」和「自己走了」。

**顺手补的一处**：`advance_account()` 此前只查账户状态，不查订阅状态。取消订阅后账户即便还是 ACTIVE 也能继续推演，属于授权来源没对上。现在先查 `subscriptions.status`。

### 前端入口（补接口之后补的，原来只有后端）

只有后端路由，页面上没有入口，等于这两个功能在界面上不存在。课题里「订阅模拟跟单」和「强平预警」要的是系统里能用，不是接口存在就算做了。

**策略与订阅页**：「我的订阅与跟单账户」从指标卡改成表格（账户 / 策略 / 本金 / 当前净值 / 浮动盈亏 / 峰值净值 / 强平线 / 状态 / 操作）。改成表格的原因是指标卡最小宽度只有 148px，塞进「持仓明细 / 取消订阅」两个按钮必然换行挤压，卡片高度不一致后 flex 排列也会乱。

- 「持仓明细」把持仓表展开在本页下方。
- 「取消订阅」带 confirm 二次确认，文案写明「记一条投资者主动取消订阅事件（不是强平）」——这两个动作在风控面板上必须能分清。按钮只在 ACTIVE 时出现：已 LIQUIDATED 的账户后端重复取消是幂等的，但不该在界面上当可用操作。

**风控与社区页**：账户表加第 9 列「操作」，风控员看到「持仓 + 手工强平」。

- 手工强平**必须填原因**，不给默认文案蒙过去。接口要 `handled_by` 和 `reason`，事后复盘时「谁按的、依据什么」比「按了」重要。
- 只有 `risk` 角色才给强平按钮。`operator` 能看账户水位，但 `liquidate` 只对 `risk` 开放，给他放个按不动的按钮等于误导。
- 本页有独立的持仓面板。这是改的时候发现并修掉的一个真问题：一开始复用了策略页的容器，风控员在本页点「持仓」，表格写到策略页去了，他在本页看不见，表现就是「点了没反应」。

**两个表格都是 innerHTML 重绘**，所以按钮用容器级事件委托（只带 `data-*` 属性），不逐行绑事件——否则每次刷新都丢。

**顺带修的口径显示**：`strategy_portfolio_nav` 是归一化净值（起点 1.0），不是金额。原来用 `money()` 渲染成「1.54」，会被读成 1.54 元，改成「×1.5380（归一化，起点 1.0）」。持仓市值合计与账户净值不是同一口径（前者是策略内单票口径的加总），页面上明写「两者不能相减」，避免被读成浮亏。

截图：`docs/screenshots/23-策略与订阅-持仓与取消订阅.png`、`24-风控页-手工强平与持仓.png`。

## 四、费率透传（改的是一个真缺陷，不只是"补个参数"）

**问题**：择时路径在 `service_backtest._run()` 里把四项成本写死（`0.0003 / 5.0 / 0.001 / 0.0005`），而 `DEFAULT_PARAMS` 的 `slippage_rate` 是 `0.0020`（当初给截面策略设的）。

**后果**：同一个系统里两套默认值。页面上改滑点对择时策略完全不生效，而且**看不出来**——回测照常跑完，只是成本假设和你以为的不一样。

**改法**：

- `DEFAULT_PARAMS` 补齐 `commission_rate / min_commission / stamp_duty_rate`，`slippage_rate` 改回择时口径 `0.0005`
- 截面路径单独用 `CROSS_SECTION_SLIPPAGE = 0.0020`（日频调仓换手高），且「用户显式传了就尊重用户的值」
- 四项成本校验从截面分支提到公共段——只在校验截面的话，择时路径传 8 会一路穿到引擎，变成 800% 的滑点
- 两条路径的 cfg 都改成从 `params` 读

**验证（不是看代码，是看产物）**：提交一次带自定义成本的 timing 回测（`0.0012 / 3.0 / 0.002 / 0.003`），读 `summary.json` 的 `config` 段逐项对比：

```
commission_rate  传入 0.0012   产物 0.0012    OK
min_commission   传入 3.0      产物 3.0       OK
stamp_duty_rate  传入 0.002    产物 0.002     OK
slippage_rate    传入 0.003    产物 0.003     OK
```

默认值另测：不传时 `0.0003 / 5.0 / 0.001 / 0.0005`；截面不传滑点时 `0.0020`，显式传 `0.001` 则 `0.001`。6 条拒绝路径（8 / −1 / 1.5 / −5 / 非数字）全部按预期报错。

验证产生的 `rate_probe` 目录与任务行已删除，`backtest_tasks` 回到 20 条。

## 五、过程中查出的第二个缺陷：CSV 的 BOM

持仓接口第一次实现时对 `api_tech` 和 `cs_test_api2` 返回 409「策略没有成交明细」，但这两个目录里 `trades.csv` 明明有数据。

**根因**：回测产物是**带 BOM 的 UTF-8**，`csv.DictReader` 把首列读成 `"\ufeffdate"`，于是每一行 `r["date"]` 都 `KeyError`，被 `except` 吞掉，`load_trades()` 静默返回空列表。

**为什么值得记**：`load_nav()` 用的是 `csv.reader` + 位置索引，完全不受 BOM 影响——所以净值曲线一直正常，只有新写的按列名取的函数踩到。同一个坑在同一个文件里只毒了一半。

**修法**：`open(..., encoding="utf-8-sig")`。

## 七、断网实测（怎么"拔网线"而不切断你我）

先说清楚为什么不能真拔网线：拔了就联系不上，这个验证没法执行。而且物理断网会同时
断掉调试通道，出问题时看不到原因。

**替代做法**：另起一个实例（8015 端口、SQLite 备份 API 拷出来的临时库副本），给这个
进程设黑洞代理：

```
HTTP_PROXY=http://127.0.0.1:1
HTTPS_PROXY=http://127.0.0.1:1
NO_PROXY=127.0.0.1,localhost
```

该进程的所有外网请求必然失败，而 8014 主实例和你我的连接完全不受影响。为了让审核
的 LLM 层真的被触发，另配 `MODERATOR_PROVIDER=dashscope` + 一个假 key。

**先查清楚系统到底哪里会出网**（不查就测等于盲测）：

| 位置 | 是否出网 |
|---|---|
| `app/static/index.html` | 否。三个引用全是 `/static/...`，无外部 URL |
| ECharts | 否。本地 `app/static/vendor/echarts.min.js`（5.5.1） |
| 研判页数据 | 否。读 `judgements` 表缓存 |
| 回测引擎 | 否。纯本地计算，`model=None`，只用现成分数 |
| `service_risk.py:356` | **是**。发帖审核的 LLM 层，唯一一处 |

**实测结果**：

1. `selftest.py --base http://127.0.0.1:8015` → **66/66 全过**。整套接口在外网不可达时可用。
2. 审核降级：选规则层不命中的帖子（#2/#3/#6）调 `moderate`，返回
   `decision=APPROVED`、`detail="仅规则层（LLM 调用失败（ProxyError））"`。
   `ProxyError` 这个异常类型本身就证明代理生效、外网确实不可达。
   规则命中的帖子（#1/#4/#5/#7）则直接 `BLOCKED`，不调 LLM——规则是硬红线。
3. 前端渲染：无头 Chrome 打开 8015，K 线、四视角散点、研判报告、财务块全部正常。
4. 回测：在断网实例上跑一次 `fusion-test-3view`，四项指标与主口径**逐位一致**：

   ```
   cum_return  0.159714041490 vs 0.159714041490
   arr         0.500602104469 vs 0.500602104469
   sharpe      3.566599483684 vs 3.566599483684
   mdd         0.036336500918 vs 0.036336500918
   ```

**结论**：断网可跑。会降级的只有审核的 LLM 层，且降级路径是设计好的、把原因写进
`llm_verdict` 而不是静默吞掉。

彩排产物已清理：`offline_check` 目录、临时库副本、8015 进程全部删除，正式库计数与
初始一致（`backtest_tasks 20 / posts 7 / post_moderation 10 / risk_events 6`）。
