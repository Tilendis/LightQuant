# 实时研判调度接口说明

> 对应课题要求 R1：「**调度**多个大模型（或不同分析视角的智能体）分别从技术面、基本面和情绪面**生成研判报告**，并通过投票或加权机制输出综合预测」。
>
> 实现日期：2026-11-14。涉及文件：`app/service_judge.py`（新增）、`app/api.py`（+2 路由）、`app/static/index.html`、`app/static/app.js`。

---

## 1. 为什么补这一个接口

课题这句话有两个动词：**调度**、**生成研判报告**。

补之前，系统里两个都只有名词：

| 环节 | 补之前 |
| --- | --- |
| 三视角结果 | `judgements` 表 62,783 行，`view` 分 tech / fund / sent |
| 怎么产生的 | `scripts/` 下三个离线脚本批量跑完写库 |
| 系统运行时 | 只读表：`GET /api/judgements/{symbol}`、`GET /api/judgements` |
| 能不能现场跑一次 | 不能。34 个路由装饰器里没有一个是触发研判的 |

于是"调度器是哪个模块"只能指到一张表，"现场换只票跑一次"做不到。对软件工程专业的课题，这是"系统"与"离线脚本 + 查询界面"的分界线。

补之后，一次请求内按顺序调度三条链路，当场返回三份报告与融合结论。

## 2. 接口契约

### `POST /api/judgements/run`

权限：`need(user, "author", "operator")`，需 `Authorization: Bearer <token>`。

请求：

```json
{
  "symbol": "万华化学",
  "date": "2024-12-02",
  "allow_llm": true,
  "write": true
}
```

- `symbol`、`date` 必填；`date` 必须是该标的的交易日（不在 `prices` 表里直接 400）。
- `allow_llm=false` 强制走情绪词典，用于无 key 或断网演示。
- `write=false` 只算不写库，用于彩排。
- `prompt_version` 可省略，省略时自动生成 `rerun-<YYYYMMDDHHMMSS>`。

响应（关键字段）：

```json
{
  "ok": true,
  "symbol": "万华化学",
  "date": "2024-12-02",
  "prompt_version": "rerun-20261114134203",
  "written": ["tech", "fund", "sent", "fusion"],
  "skipped": [],
  "views": {
    "tech": {"status": "ok", "score": -0.0872, "signal": "HOLD",
             "reason": "BiLSTM 估计次日上涨概率 45.6%（阈值 50%），判为中性，近 5 日 RSI6 66.2、MACD柱 -0.4949、BIAS5 +0.02",
             "provider": "local", "model": "bi_lstm_feat10", "source": "live", "ms": 22},
    "fund": {"status": "ok", "score": 0.36, "signal": "BUY",
             "reason": "PE 处历史 51% 分位、PB 处历史 4% 分位，综合估值分 +0.36，估值偏低",
             "provider": "local", "model": "valuation_percentile", "source": "offline_rule", "ms": 2},

             "reason": "未走大模型（未配 ZHIPU_KEY），按情绪词典命中 无涨跌词，判为中性",
             "provider": "local", "model": "sent-lexicon-v1", "source": "offline_rule", "ms": 2}
  },
  "fusion": {"score": -0.1147, "signal": "HOLD",
```

`status` 三种取值：`ok`（产出结论）、`skip`（没有材料，弃权）、`error`（链路本身失败，带 `error` 字段）。

### `DELETE /api/judgements/run/{prompt_version}`

权限同上。只允许删 `rerun-*`，传主口径版本号会被 400 拒掉。返回 `{prompt_version, deleted}`。

## 3. 三条链路怎么调度（与离线脚本的对应关系）

调度**不新增算法**，三条链路的判定逻辑与 `scripts/` 下对应脚本逐行一致。

| 视角 | 调度内容 | 实现来源（逐项对齐） | 实测耗时 |
| --- | --- | --- | --- |
| 技术面 | `Backtest_Dataset` 取 5 日窗口 → `BiLSTM` 前向 → `score = 2p - 1` | `scripts/gen_tech.py`：同 `DEFAULT_COLS` 十维、同 `result/CSMD50_w5_feat_bi` 权重、同 `look_back=5`、同 `score_to_signal(th=0.2)` | 22 ms |
| 基本面 | 取 `date<=d` 的估值序列 → PE/PB 历史分位 → 0.6/0.4 加权 → clamp ±1 | `scripts/gen_fundamental.py`：同 `pct_rank`（`len<8` 返回 None）、同 `fund_score`、同"不插值不回填"的对齐红线 | 2 ms |
| 情绪面 | 读当日新闻 CSV → 智谱 `glm-5.3-flash`，失败降级 `glm-4.7-flash`，再失败降级情绪词典 | `scripts/gen_sentiment.py`：同 `BASE_URL`、同 prompt 契约（score/confidence/reason/evidence）、同 `temperature=0` | 2 ms（规则降级） |
| 融合 | 0.90 / 0.00 / 0.10 加权，按可用视角归一化；fund 与 sent 先去当日截面均值 | `scripts/fuse_views.py`：同 `WEIGHTS`、同 `demean`、同 `to_signal(th=0.2)` | 毫秒 |

技术面注意点：模型 `forward` 末尾已有 `Sigmoid`，代码不再套一次，并保留区间校验（输出越界直接 `error`，不会静默写错数据）。

## 4. 四个必须说清的边界

### 4.1 写独立版本，不动主口径

新结果写 `prompt_version = rerun-<时间戳>`。主口径 `fusion-test-3view` 一行不动。

这条是为了让"现场演示"变成可做动作：跑十次、删十次，主口径数据始终是 62,783 行。实测：跑一次写 4 行（12-02）→ 全库 62,787 → `DELETE` → 回到 62,783。

界面上也是分开的：上面一块是**现场调度结果**，下面是**主口径研判报告**，两者日期和版本号都标出来，不会混读。

### 4.2 没有材料就弃权，不落 HOLD

情绪面当日没有新闻时返回 `status: "skip"`，**不写库**。

理由与 `scripts/gen_agents.py` 的既有语义一致：落一条 HOLD 在投票里就是一张实打实的反对票。tech HOLD + sent HOLD 就凑成两票，fund 判什么都不算了。所以"没信息"必须与"判中性"区分开。

融合时 `skip` 的视角不参与，按剩余可用权重归一化；返回里 `skipped` 字段明列弃权视角。

### 4.3 无 key 时降级，且标明是规则分

没有 `ZHIPU_KEY` 或 `allow_llm=false` 时，情绪面走情绪词典（正/负词命中数差值 × 0.6），写 `model='sent-lexicon-v1'`、`source='offline_rule'`，理由里写明"未走大模型"。

不把规则分说成大模型研判，这条在 `docs/基本面口径与财报事件验证.md` 里已经反复强调过，此处同样适用。

### 4.4 去均值需要横截面，单标的时怎么处理

`fuse_views` 对 fund 和 sent 做"按日截面去均值"，是为了去掉视角自身的乐观/悲观底噪（实测情绪面 50 条里 32 条 BUY，均分 +0.46）。技术面**不做**——它的概率是绝对值，去掉就没有意义。

但只调一只票时没有横截面。这里的处理是：取**当日库里已有同版本分数**算均值（fund 用 `fund-rule-v1`，sent 用 `sent-v1`）；当日不足 5 只时**退化为不去均值**，并在返回的 `demean` 里写明 `applied: false` 与原因，不假装做过。

实例（12-02）：sent 当日库里 12 只有分、均值 +0.3625。万华化学当日词典分 0.00，去均值后变成 −0.3625——含义是"同期其他标的整体偏乐观，这只票没消息，相对就不乐观"。这是去均值的正常结果，不是算错。

## 5. 现场怎么验（三步，两分钟）

前提：服务在 `http://127.0.0.1:8014` 跑着。

**第一步：界面**

1. 页面右上角切到「策略作者」；
2. 「行情研判」页，K 线下方有「研判日期 + 重新研判」；
3. 日期填 `2024-12-02`（万华化学最后一条新闻是这一天，三视角都有料），点「重新研判」；
4. 2 秒内出结果：技术面 / 基本面 / 情绪面 / 融合四行，各带信号、理由、模型、耗时；脚注写清哪一路去了均值、哪一路弃权。

   这一屏的样子见 `docs/screenshots/25-研判页-重新研判调度.png`：上方是现场调度结果，下方是主口径研判报告，两块日期与版本号都标出来，不会混读。

**第二步：确认没动主口径**

```powershell
.\.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'.');from app import db;c=db.connect();print(c.execute('SELECT COUNT(*) n FROM judgements WHERE prompt_version=\'fusion-test-3view\'').fetchone()['n'])"
```

## 7. 已知局限（答辩时要主动说）

1. **技术面标准化用该股全序列均值方差**。这是继承自原仓库 `standardize_dataframe` 的做法，用到了测试期之后的信息，属于前视泄漏。本次未修正，返回里已标注，与 `docs/工程化收尾说明.md` 的表述一致。
2. **情绪面覆盖稀疏**。全 test 段只有 21.57% 的交易日有新闻，12 月仅个别日期。调度本身没问题，但演示要挑有新闻的日子，否则该视角弃权；弃权是正确行为，不是失败。
3. **单标的调度没有真横截面**。去均值用的是"当日库里已有分数"，不是"现场重算 50 只"。两者在数值上可能有极小差异（若库里某只票的分数来自不同批次），但语义一致。
4. **串行调度**。三条链路顺序执行，没有并发。当前耗时在 100 ms 级，没有并发的必要；若将来接入更慢的模型，可改 `ThreadPoolExecutor`（`service_backtest.py` 已有同类实现可参照）。
5. **不写 `backtest_tasks`**。研判调度是轻量同步操作，不进异步任务表；只有回测走那条 PENDING/RUNNING/SUCCEEDED 的状态机。
