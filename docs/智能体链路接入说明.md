# 智能体链路接入说明（方案 A：2024-12 演示链路）

## 一、做了什么

把 `scripts/gen_agents.py` 产出的三分析师结论接进线上主链路：前端「行情研判」页与 K 线叠加信号，
在 2024-12-16 ~ 12-31 显示三智能体研判，其余日期自动回退到基线版本。

没有重跑全 test 段，没有新增 API 调用成本。

## 二、版本映射与回退规则

| 视角 | 智能体版（优先） | 基线版（回退） |
|---|---|---|
| 技术面 | `tech-agent-v1` | `tech-v1` |
| 基本面 | `fund-agent-v1` | `fund-rule-v1` |
| 情绪面 | `sent-agent-v1` | `sent-v1` |
| 融合 | `fusion-agent-v1` → `fusion-test-3view` → `fusion-val-3view` | 三段都不存在时无值 |

融合一列在 2026-11 之后变成**三段优先链**，不再是"智能体版 / 基线版"二元：

| 版本 | 日期覆盖 | 权重 | 用途 |
|---|---|---|---|
| `fusion-agent-v1` | 2024-12-16 ~ 12-31（12 天） | tech 1.0 / fund 0 / sent 0.5 | 三智能体链路内部合成 |
| `fusion-test-3view` | 2024-08-08 ~ 12-31（97 天） | tech 0.90 / fund 0.00 / sent 0.10 | 验证集标定，样本外段 |
| `fusion-val-3view` | 2024-03-15 ~ 08-07（98 天） | tech 0.90 / fund 0.00 / sent 0.10 | 验证集标定，样本内段 |

三段日期不重叠，所以"逐日取第一个有记录的版本"就够，不需要按日期硬切。
**注意 `fusion-agent-v1` 与另外两段不是同一套权重**（1.0/0/0.5 vs 0.9/0/0.1），
前端表头必须分开写，混写会让界面自相矛盾。

（改动前的二元写法"`fusion-agent-v1` / `fusion-val-v1`"已作废：`fusion-val-v1` 是
旧标定 tech=1.0，不是验证集三方标定的产物。）

规则：同一天里，智能体版有记录就用智能体版；没有就用基线版。
接口层用 `prompt_version=auto` 表达这个语义，逐日比对、不做混排。

## 三、改动清单

### 1. `app/api.py`

- 新增 `PV_PREF`（版本映射表，融合为三段优先链）与 `pick_by_date()`（逐日取优先版本）
- `/api/market/kline/{symbol}`
  - 原来 SQL 里把 `tech-v1 / fund-rule-v1 / sent-v1` 写死，改为按 `PV_PREF` 逐日取
  - `fusion_version` 默认值由 `fusion-val-v1` 改为 `auto`
- `/api/judgements/{symbol}`
  - 新增 `prompt_version=auto` 分支；显式传版本时行为不变

### 2. `app/static/app.js`

- `VER` 四个值全部改为 `auto`
- `renderJudge()` 表头文案按当日实际 `prompt_version` 切换：
  智能体日期写「三视角均由大模型智能体独立研判」，基线日期写「技术面＝本地 BiLSTM／基本面＝本地规则」
- 智能体日期不再追加「技术面·大模型解读」行（该行是给本地模型补理由用的，智能体本身已是 LLM 判断）
- 智能体日期不显示编排层行（编排层未跟着重跑，输入仍是旧视角，并排会出现逻辑错位）
- 情绪面缺失说明区分两种原因：智能体日期为「无新闻覆盖、弃权不落库」，基线日期为「ffill 外推」
- 基本面「离线预计算」标签只在 `fund-rule-v1` 上豁免，智能体版照常标注

### 3. `scripts/build_fusion_agent.py`（新增）

- 读三个智能体视角，按 `WEIGHTS = {tech:1.0, fund:0.0, sent:0.5}` 合成 `fusion-agent-v1`
- 缺失视角时只对有记录的视角求和，分母同步缩小
- `reason` 写明每个视角的分数、权重、自评信号与合成结果
- `reason` 追加冲突说明：某视角自评 HOLD 但分数越过 ±0.05 时，注明「由融合层按分数定方向」

- `docs/exp_agents_pilot.json`：恢复 12-16 ~ 12-30 主结果（补跑 12-31 时被覆盖，已按库内记录重算）

## 五、两件必须在论文里说清的事

### 1. 加权层会与分析师自评的 HOLD 不一致

融合层只读连续 `score`、不读单视角的 `signal`。技术面 95% 的结论是 HOLD，
其中一部分给了略偏空的分数（如 -0.08），按 ±0.05 阈值会被判成 SELL。

实测 600 条融合里有 73 条出现这种「技术面写 HOLD、融合写 SELL」的情况，
`reason` 里已逐条注明。这不是 bug，是「用连续分数提取微弱方向」的代价，
但界面上一行 HOLD、一行 SELL 会被追问，必须主动交代。

### 2. 情绪面在 12 月大量弃权，融合退化为技术面单视角

新闻按标的×日期覆盖 920/4850 ≈ 18.97%。12 月 50 只标的里 46 只在多数交易日没有新闻，
情绪面智能体按纪律弃权不落库。缺 sent 时融合分母只剩 tech（fund 权重为 0），
结果等于技术面分数本身。

所以「三视角融合」在多数标的上实际是「技术面主导 + 情绪面偶尔加分」，
不能写成「三视角等权投票」。

## 七、论文口径：能说与不能说

**能说**

- 智能体重构覆盖 2024-12-16 ~ 12-31，三视角均由大模型独立研判，各自调用本地指标、估值分位、新闻作为工具，彼此信息隔离
- 融合按验证集标定的权重合成，基本面权重为 0 有明确依据
- 其余日期为基线版本（本地 BiLSTM + 规则 + 旧 LLM），系统按日期自动选择

**不能说**

- 「全 test 段都是三智能体研判」（只覆盖 12 月）
- 「融合提升了预测能力」（0.6098 vs 情绪面单视角 0.6176，基本持平）
- 「三视角等权融合」（基本面权重为 0，且情绪面大量弃权）
